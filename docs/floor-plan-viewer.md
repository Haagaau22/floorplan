# Floorplan 户型工具方案

> 状态：整体方向已确认，供后续开发和数据整理使用
>
> 更新日期：2026-11-17

## 项目定位

Floorplan 是一个通用的户型查看与测量工具。它把 CAD 户型整理成结构化 JSON，再由网页还原图纸、测量距离和面积，并展示与空间相关的业务数据。

仓库和域名不绑定某一套公寓或瓷砖项目。首个项目是当前的32套公寓，后续可以继续接入其他户型。

第一阶段只提供只读网页。人负责查看和测量，Agent 通过统一数据接口修改 JSON，暂不开发人工画图功能。

## 第一阶段范围

当前公寓项目包含：

- 复现 CAD 中32套带房号的房间和公共走廊。
- 保持墙体、门窗、文字、尺寸和空间边界与原 CAD 一致。
- 支持缩放、平移、图层显示和房间查询。
- 支持任意两点距离测量和多点面积测量。
- 点击已识别空间时，直接查看面积、周长及瓷砖数据。
- 同时适配电脑、平板和手机。

第一阶段不包含：

- 人工在网页中画墙、移动墙体或保存修改。
- 用户账号、权限和多人协作。
- 在浏览器里直接解析或修改 DWG。
- 不属于当前项目的无房号区域。

## 整体结构

正式网页使用独立域名 `floorplan.221231.xyz`。域名直接指向香港节点，用户不需要直接访问 Cloudflare。

```text
大陆用户或 Agent
        |
        v
+---------------------------+
| 香港节点 Caddy            |
|                           |
| 普通网页请求 ---> Vue 页面 |
| 数据请求 -------> API 中转 |
+---------------------------+
                  |
                  v
        +-------------------+
        | Cloudflare Worker |
        | 读取、校验、写入   |
        +-------------------+
                  |
                  v
        +-------------------+
        | Cloudflare R2     |
        | 唯一户型数据存储   |
        +-------------------+
```

香港节点只托管网页并中转数据请求，不运行额外的 Node 或 Python 后端，也不保存 JSON 副本。Cloudflare Worker 是数据后端，R2 是唯一数据存储。

## 数据如何读写

网页和 Agent 使用同一个香港域名访问数据。读取公开，修改需要授权。

```text
查看户型

Vue 网页 --> 香港 Caddy --> Worker --> R2
                                     |
Vue 网页 <-- 香港 Caddy <-- Worker <--+


修改户型

Agent --> 香港 Caddy --> Worker 验证身份和数据 --> R2
```

Caddy 把数据请求原样转发给 Worker，因此浏览器只连接香港节点，也不需要处理跨域。Worker 通过 R2 的内部连接读写数据，写入密钥不会出现在 Vue 或香港服务器中。

整个过程只有一份户型 JSON，不存在 Git 数据副本、香港数据镜像或多处同步。

## 各部分职责

| 部分 | 职责 |
|---|---|
| Vue 网页 | 绘制户型、响应式展示、测量和数据查询 |
| 香港 Caddy | 提供公开网页，并把数据请求转发给 Worker |
| Cloudflare Worker | 提供统一数据入口，验证修改权限和 JSON 内容 |
| Cloudflare R2 | 保存唯一的户型 JSON 和项目数据 |
| Agent | 通过统一接口读取、修改并提交户型数据 |
| GitHub 仓库 | 保存程序、转换脚本和文档，不保存项目户型数据 |

原始 DWG 是户型转换和准确性复核的依据。已经整理出的核准规则、现有测量值和待复核项继续保留，但最终都应通过统一接口进入 R2，不能因为进入网页而自动视为已经核准。

## 技术方向

| 部分 | 选择 | 原因 |
|---|---|---|
| 网页框架 | Vue 3 + TypeScript + Vite | 适合响应式单页工具，并能打包成静态网页 |
| 户型绘制 | SVG | 缩放后保持清晰，便于图层、点选和精确测量 |
| 远程数据 | TanStack Query | 统一处理数据加载、缓存、刷新和异常状态 |
| 统计表格 | TanStack Table | 用于房间和瓷砖统计的排序、筛选和展示 |
| 页面路由 | Vue Router | 需要多个页面时再启用 |
| 数据校验 | JSON Schema | Agent 提交后检查格式和必要数据是否完整 |
| 数据后端 | Cloudflare Worker | 提供轻量读写接口，并直接连接 R2 |
| 数据存储 | Cloudflare R2 | 作为所有户型项目的唯一数据存储 |
| 对外入口 | 香港节点 Caddy | 提供大陆访问路径和 API 中转 |

TanStack Router 当前不支持 Vue，因此不纳入项目。香港节点不再部署单独的应用后端。

## 响应式查看方式

户型坐标和比例始终保持不变。响应式设计只调整查看窗口和操作面板，不会为了适配手机而改变房间形状。

```text
电脑：户型主视图 + 常驻信息面板

平板：户型主视图 + 可收起信息面板

手机：全屏户型视图 + 底部工具栏 + 上拉信息面板
```

手机端通过缩放和平移查看细节，统计信息使用适合窄屏的布局。距离和面积测量同时支持鼠标和触摸操作。

## 准确性要求

“复现 CAD”要求几何关系和测量结果一致，不能只把 CAD 截图放进网页。

```text
JSON 绘制结果与 CAD 半透明叠加
              |
              v
检查墙体、门窗、文字和空间边界是否重合
              |
              v
抽查 CAD 标注尺寸与网页测距结果
              |
              v
核对房间面积、走廊面积和项目总量
```

转换初期先选择普通开放式厨房、封闭厨房和复杂边界三类代表户型进行验证。三类都能准确还原和测量后，再处理全部32套和走廊。
